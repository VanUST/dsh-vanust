# Терминология проекта

Один смысл — одно слово. Это словарь для всего, что агент говорит владельцу: отчёты, ответы,
заметки в задачах, сообщения в коммитах. Английские идентификаторы (имена инструментов, коды,
пути) остаются дословными и приводятся как доказательство, а не вместо объяснения.

## Как пользоваться

1. Прежде чем писать отчёт, найди здесь каждое существительное, которое называет сущность.
2. Термина нет в словаре — объясни понятие одной фразой. Если оно нужно надолго, добавь его
   сюда в той же задаче: слово, идентификатор, определение и формулировку для владельца.
   Не используй термин до того, как он определён.
3. Не придумывай синонимы: одно понятие называется одинаково в каждом отчёте. Не переименовывай
   понятие, которое ввёл владелец, — принимай его слово.
4. Внутреннее имя — не подлежащее. Сначала факт человеческим языком, потом идентификатор в
   скобках: «прогон отказан, потому что сохранённая команда изменилась (`COMMAND_MISMATCH`)».

## Отчёт

| Слово | Идентификатор | Что это | Как говорить |
|---|---|---|---|
| Итог | outcome, TL;DR | первая строка отчёта: что получилось, в одном-двух предложениях | «итог» |
| Изменения | changes | что именно изменилось, по областям | «изменения» |
| Доказательства | evidence | команды, вывод, код возврата и файлы, подтверждающие результат | «доказательства» |
| Решения | decisions | что выбрано и почему | «решения» |
| Риски | risks | что не проверено и что может сломаться | «риски» |
| Дальше | next actions | следующее действие, если оно нужно | «дальше» |

## Люди и роли

| Слово | Идентификатор | Что это | Как говорить |
|---|---|---|---|
| Оркестратор | orchestrator | корневой агент: планирует, ставит задачи, принимает результат и отчитывается | «оркестратор» |
| Архитектор | architect | роль системного дизайнера на дорогой модели: решает, что должно существовать и как части сходятся; контекст получает от оркестратора или от сборщиков контекста | «роль ARCHITECT» |
| Специалист | specialist, child | делегированный агент одной роли, работает по брифу | «специалист BACKEND» |
| Роль | role | профессия специалиста и его набор инструментов | «роль REVIEWER» |
| Пресет | preset | набор инструментов, инструкций и правил, который получает агент | «пресет» |
| Бриф | brief | постановка задачи специалисту: цель, объём, критерии приёмки, доказательства | «бриф» |

## Работа

| Слово | Идентификатор | Что это | Как говорить |
|---|---|---|---|
| Задача | task | запись в таскборде с целью, объёмом и критериями приёмки | «задача» |
| Таскборд | taskboard, Tasks panel | журнал задач воркспейса | «таскборд», «панель Tasks» |
| Исполнитель | owner | кто выполняет задачу: специалист или сам оркестратор | «исполнитель» |
| Критерии приёмки | acceptance | проверяемые условия, при которых задача считается выполненной | «критерии приёмки» |
| Объём / вне объёма | scope / non-scope | что задача трогает / чего не касается | «объём», «вне объёма» |
| Передача работы | handoff | передача незавершённой работы следующей сессии | «передача работы» |
| Цель | goal | долгоживущий результат, который сессия доводит до конца | «цель» |
| Журнал проекта | project ledger, `state/` | файлы REQ/TASK/TEST/DECISION и их события, общие для всех машин проекта | «журнал проекта» |
| Коллизия в журнале проекта | state collision | при слиянии: два файла с одним номером или одна запись под двумя номерами | «коллизия в журнале проекта» |

## Требования и анализ

| Слово | Идентификатор | Что это | Как говорить |
|---|---|---|---|
| Требование | requirement (BR/FR/NFR) | то, что должно быть верно для пользователя или системы | «требование» |
| Запись анализа | Analysis Record | документ с бизнес-результатом, требованиями и связью требований с задачами | «запись анализа» |
| Инициатива | initiative | одно изменение, на которое заводится запись анализа | «инициатива» |
| Трассировка | trace | связь требование → задача → доказательство | «трассировка» |
| Приём требования | intake | запись требования владельца в библиотеку кейсов до реализации | «приём требования» |

## Проверки и доказательства

| Слово | Идентификатор | Что это | Как говорить |
|---|---|---|---|
| Кейс | case | сохранённая проверка требования: шаги, ожидаемый результат, доказательство | «кейс» |
| Прогон | run | одно выполнение сохранённой команды кейса | «прогон» |
| Проверка | check | условие, которое оценивается по измеренному значению (порог, хеш) | «проверка» |
| Измерено | measured | значение получено прогоном, а не введено вручную | «измерено» |
| Вручную | manual | результат ввёл человек или агент, он не измерен | «подтверждено вручную» |
| Доказательство | evidence | команда, её вывод, код возврата, файл — то, что подтверждает результат | «доказательство» |
| Артефакт | artifact | файл прогона: лог, скриншот, отчёт | «артефакт» |
| Базовая линия | baseline | записанное значение, с которым сравнивается новый прогон | «базовая линия» |
| Негативный контроль | negative control | намеренно сломанный прогон, доказывающий, что проверка умеет падать | «негативный контроль» |
| Подтверждён | verified | есть измеренный успешный прогон и записанный контрольный отказ | «подтверждён прогоном» |
| Устарел | stale | файл из проверки изменился после последнего прогона | «кейс устарел» |
| Нестабилен | flaky | повторные прогоны дают разный результат | «проверка нестабильна» |
| Условие приёмки | gate | правило, которое не даёт закрыть работу без доказательства | «условие приёмки» |
| Расхождение | drift | записанный отпечаток файла не совпал с текущим | «расхождение» |
| Кейс приёмки | acceptance case | кейс, который может закрыть задачу: его пишут для проверки чужой работы | «кейс приёмки» |
| Тестировщик | tester | отдельная роль, которая пишет кейс приёмки и его драйвер, измеряет красный прогон на прошлой версии и зелёный на изменении; продуктовый код не правит | «тестировщик» |
| Красный на неверном продукте | wrong-product red | прогон теста против прошлой версии или названной неверной реализации: тест обязан там упасть | «красный на неверном продукте» |
| Пакетное ревью | batch review | одна задача ревью и один REVIEWER на 2–8 задач: бриф содержит контракт каждой, ответ — вердикт по каждой | «пакетное ревью» |
| Вердикт по задаче | per-task verdict | `pass` или `fail` с находками и доказательствами для одной задачи из пакета; проверяемые задачи закрывает оркестратор по одной | «вердикт по задаче» |
| Контракт задачи | task contract | то, против чего задачу принимают: цель, объём, что не трогать, критерии с id, ограничения, форма доказательства | «контракт задачи» |
| Уровень проверки | verification level | насколько дорого доказывается задача: `proof` — прогнать продукт и процитировать; `case` — то же плюс кейс, если поведение стоит закрепить; `independent` — кейс пишет и измеряет другой пресет, и каждый критерий покрыт | «уровень проверки» |
| Критерий приёмки | acceptance criterion (AC-n) | проверяемое утверждение с постоянным id; кейс называет его через `criterionId`, а закрытие считает покрытие | «критерий AC-1» |
| Покрытие критериев | criteria coverage | сколько критериев задачи закрыто допустимым кейсом, который их называет; для уровня `independent` обязано быть полным | «покрытие критериев» |
| Кейс исполнителя | implementation case | кейс, который исполнитель написал для собственной работы; задачу он не закрывает | «кейс исполнителя» |
| Происхождение доказательства | provenance | кто написал кейс и кто выполнил прогон: пресет и сессия, записанные в кейсе | «происхождение доказательства» |
| Исполнитель задачи | implementer | пресет, который выполнил работу в задаче; его сравнивают с автором кейса и с тем, кто прогонял | «исполнитель задачи» |
| Самопроверка | self-verification | исполнитель сам подтверждает собственную работу | «самопроверка» |
| Плейбук пресета | preset playbook | короткий блок в персоне роли: механизм, с которым роль встречается (оркестрация, журнал, библиотека кейсов), и анти-паттерны её обычной нагрузки | «плейбук пресета» |
| Ложное положительное завершение | false positive completion | задача закрыта, хотя её утверждение неверно: работа не сделана, сделана не там или не доказана | «ложное положительное» |
| Ложное отрицательное завершение | false negative completion | работа верна, но процесс её отверг: отказ по неверной причине, непринятое доказательство, лишняя проверка | «ложное отрицательное» |
| Анти-паттерн | anti-pattern | способ работы, который выглядит продуктивным, но ведёт к ложному завершению; в ките — к ложному положительному или ложному отрицательному | «анти-паттерн» |

|---|---|---|---|
| Панель | panel | раздел боковой панели интерфейса | «панель Tasks» |

| Инструмент | tool | вызываемая агентом операция с именем и схемой аргументов | «инструмент» |
| Харнесс | harness | среда, в которой работают агенты: сессии, инструменты, модели | «харнесс» |
| Маршрут модели | model route, provider route | провайдер и модель, которым уходит запрос | «маршрут модели» |
| Повтор запроса | retry, retryPolicy | повторный запрос к модели, когда предыдущий ответ непригоден: оборвался, вернул ошибку провайдера или невалидный JSON аргументов инструмента | «повтор запроса» |
| Шаг | step | один запрос к модели: сборка промпта, ответ, вызовы инструментов; шаг/start и шаг/end в журнале | «шаг» |
| PTC | ptc, run_code | режим, в котором модель вызывает инструменты программой: единственный прямой инструмент `run_code`, остальные — функции сгенерированного SDK | «PTC» |

## Запрещённые заменители

Эти слова не используются в общении с владельцем; в скобках — чем заменить:

- «гейт» → «условие приёмки» или «проверка»;
- «дрифт» → «расхождение»;
- «фолс-позитив» / «фолс-негатив» → «ложное положительное» / «ложное отрицательное»;
- «пруф» → «доказательство»;
- «провенанс» → «происхождение доказательства»;
- «оверлей» → «временный слой настроек»;
- «манифест» → «список файлов сборки»;
- «интейк» → «приём требования»;
- «зелёный / красный путь» → «успешный / неуспешный прогон»;
- составные внутренние имена вида «case-library drift» → сказать факт: «кейс устарел, потому
  что изменился файл»;
- идентификатор в роли подлежащего («`COMMAND_MISMATCH` означает…») → «прогон отказан, потому
  что сохранённая команда изменилась (`COMMAND_MISMATCH`)».

## Язык

- Проза — на языке владельца; в этом проекте это русский. Идентификаторы, пути и коды —
  дословно английские, в обратных кавычках.
- Не переводи идентификаторы калькой: называй действие по-русски, идентификатор приводи в
  скобках.
- Аббревиатуру расшифровывай при первом употреблении: «критерии приёмки (acceptance)», а не
  «AC» без пояснения.
