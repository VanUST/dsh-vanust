# A stale generated spec is advisory; an edited, missing or orphaned one still blocks

## What was decided

The in-force law `shipped-plugins.specs-cannot-drift-silently` (ADR 0012, ratified by 0013)
treats four drift situations as one blocking problem: a generated spec document that was
hand-edited, one that is missing while the project tracks generated specs, one that is stale
(unedited, but written from an older law set), and — added later — one that is orphaned because
no decision in force generates it any more.

That law is narrowed. Only the hash-behind kind (`stale`) becomes advisory. A `stale` document
is reported with the withdrawal note the ratchet drafts for it and does NOT enter the blocking
problem list; a `drifted` (hand-edited), `missing`, or `orphaned` document still blocks, because
each is evidence that the human-readable view is WRONG rather than merely old.

## Why

A stale document is unedited and structurally correct. It was generated by the ratchet from a
law set that has since moved, and the only act it needs is a regeneration
(`ratchet compile --write`). A gate that is red over a document that needs regenerating is a
gate people learn to disable or work around — the same failure mode this kit's own LIMITATIONS
records for a status that is red on the first run of a new project. The three other kinds are
different in kind: a hand edit means a person overwrote generated output; a missing document
means the human-readable view is gone; an orphan belongs to no decision in force. Those are
reported as problems because they are not fixed by a regeneration alone.

The decided behaviour is recorded in LIMITATIONS.md §3.4:

> A stale specification is reported with a drafted withdrawal note and never blocks the gate.
> Decided 2026-09-16: only the hash-behind kind becomes advisory — a hand-edited, missing or
> orphaned document still blocks.

## Why an amendment and not an edit

ADR 0012 is in force through a human ratification (approval 0013). Its law text and its source
are frozen with that consent: editing either voids the consent (`RATIFICATION_STALE`) and the law
leaves force, and re-declaring the same law id is the corpus contradicting itself. The change
therefore ships as this amendment: it removes the old law id and restates the narrowed rule
under the new id `shipped-plugins.spec-stale-is-advisory-others-still-block`, bound to the
command that actually fails when the narrowing stops holding.

## The withdrawal note is drafted by the ratchet, not by an agent

The note a stale document is reported with is produced by the ratchet's own drafting pass
(`ratchet-drafts.mjs`, `draftNeedsHuman`), which `ratchet compile` invokes and the ADR panel's
read-only view also runs. No agent and no model decides to write it; the ratchet detects the
stale document and drafts the note under `reports/ratchet/drafts/`, never applying it — it never
deletes or regenerates the document. That separation is the point: the detection is the
ratchet's, the act is the human's.

## The check

`node scripts/check-gate-invariants.mjs` is the enforcement point, and the law's statement is
narrowed to exactly what that command asserts. It compiles a corpus with generated specs,
corrupts one situation at a time, and requires each verdict:

- a stale document is reported in the compile/verify `specDrift.stale` list WITH a drafted
  withdrawal note path, and is NOT a `SPEC_OUT_OF_DATE` problem;
- a hand-edited document is a `SPEC_HASH_MISMATCH` problem;
- a deleted tracked document is a `SPEC_OUT_OF_DATE` problem;
- an orphaned document (the zone renamed under it) is a `SPEC_ORPHANED` problem;
- a compile that persists a bundle without regenerating the document leaves the document stale,
  which is reported and advisory;
- a freshly regenerated corpus verifies clean.

The command was itself updated to these expectations, and its previous assertion — that a stale
document is a blocking `SPEC_OUT_OF_DATE` — is the revert counterexample: restoring that
assertion makes the command fail against the implemented behaviour, so the check cannot be
satisfied by a green run of a suite whose covering test was emptied.

## Status

This record is `proposed` and awaits a human ratification. Until a human ratifies it the old
law `shipped-plugins.specs-cannot-drift-silently` remains in force. A known interaction is
recorded plainly: the ratchet's ratification queue reads any proposed record that removes law
in force as a decidable contradiction and blocks it, so this amendment is reported as a
contradiction with no drafted resolution (the ratchet recognises an amendment that restates the
decision under a new law id and drafts nothing against it). Making the queue OFFER an amendment
to a human instead of refusing it is a separate change to a ratified rule and is not made here.
