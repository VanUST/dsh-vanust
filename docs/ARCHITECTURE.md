# Архитектура DSH kit

Дата проверки: 2026-11-28

Границы, компоненты с владельцами и путями, контракты, инварианты с проверкой, путь запроса: вписывается ли новая фича. Процедуры — [DEPLOYMENT](../rules/DEPLOYMENT.md), команды — [GUIDE](GUIDE.md), слова — [TERMINOLOGY](TERMINOLOGY.md).

**Происхождение.** Проект без архитектуры получает описание, выведенное из кода; оно не подтверждено архитектором, пока он его не принял.

## 1. Границы подсистем

| Подсистема | Владеет | Не владеет |
|---|---|---|
| Харнесс | сессиями, шагом модели, инструментами шага, сборкой и отправкой запроса, субагентами | требованиями, критериями приёмки, статусом задач |
| Профиль, пресеты, установщик | ролями и подключением плагинов; закреплённой версией и переходом | правилами задач, реализацией шага модели |
| Плагины кита | записью анализа, таскбордом, кейсами, журналом; каждый — только своё состояние | форматом запроса провайдера; приёмкой |
| Оркестратор | приоритетом, объёмом, порядком задач, вызовом ролей, приёмкой | записью результата вместо исполнителя |
| Провайдер модели | сериализацией у себя, совпадением префикса, счётчиками токенов | правилами кита о составе запроса |

Правила переходов и проверки плагинов принимают обычные данные кита и не импортируют модули харнесса; `ctx`, события и вызовы сессий — на входе конкретного плагина. Смена формы запуска не требует менять критерии и кейсы: один сценарий проверяет обе установки, различая исходники, файлы установки и состав плагинов.

## 2. Компоненты, владельцы, контракты

| Компонент и путь | Что держит → кому отдаёт |

| Ядро состояния `plugins/project-state/` | журнал `state/events.jsonl`, записи, `state/views/` → таскборд, анализ |
| Таскборд `plugins/taskboard/` | строки задач, закрытие, проверка записи → журнал, приёмка |
| Запись анализа `plugins/analysis/` | `docs/analysis/<id>.json`, требования → оркестратор, таскборд |
| Кейсы `plugins/test-cases/`, `docs/cases/` | запись, прогон, дрейф → таскборд, тестировщик |

| Карта дизайна `plugins/designmap/` | страницы-рисунки → панель |
| Презентации `plugins/presentation/` | колода и дашборд одним файлом → панель |

| Развёртывание `profile/` — владелец установщик | состав профиля и патчи установленного харнесса → харнесс при запуске |

Детали: `plugins/project-state/README.md`, `plugins/test-cases/README.md`, [cases/README](cases/README.md).

**Остальные плагины — не компоненты архитектуры.** У каждого свой README, их каталог — `docs/GUIDE.md`; проверка границ перечисляет их файлы как «вне компонентов», и это ожидаемое состояние, а не долг: компонент здесь — только то, что держит границу, контракт или инвариант.

## 3. Шов харнесса

`ctx.subagents.startActivation(spec)` — единственный вызов, чья форма зависит от версии харнесса. Владелец формы — `harness-seam.mjs` (`activationSpec`, `ACTIVATION_FORMS`); в `orchestrator.mjs` полей спеки нет. Формы: вложенная (`spec.request.parent`, `maxDepth`, `outputSchema`) и плоская (`spec.parent`, `spec.prompt`, `spec.agentPreset`, `spec.cwd`); по умолчанию обе, каждая читает свои поля. Новая версия — правка только `harness-seam.mjs`; проверки — `test/harness-seam.test.mjs`, `scripts/dsh-migration-proof.mjs`.

| Остальные вызовы, все из `orchestrator.mjs` | Проверка |
|---|---|
| `ctx.subagents.getProvider(name)` | `test/delegation-basis.test.mjs`, `test/board-limit.test.mjs` |
| `ctx.subagents.sendMessage(parent, childId, blocks, {signal})` | `test/delegation-basis.test.mjs` |
| `ctx.subagents.interrupt(childId, {kind:'ancestor', agent})` | `scripts/taskboard-close-stop-proof.mjs` |
| `ctx.on('agent/created')`, `session/event`, `ctx.get(...)` | тесты делегирования |

Новый вызов — сюда же.

## 4. Инварианты и их проверка

| Инвариант | Чем проверяется |
|---|---|
| Запуск субагента — одна форма в одном месте; неизвестная форма — отказ | `test/harness-seam.test.mjs`, `scripts/dsh-migration-proof.mjs` |
| Кейс говорит о поведении через публичную поверхность: `surface`, `interactions`, `failureKind`, исполняет драйвер | `make cases`, [behaviour-only-cases](analysis/behaviour-only-cases.json) |
| Кейс закрывает задачу только измеренным прогоном; автор и исполнитель прогона не исполнитель | `case_gate`, гейт таскборда |
| Ложная запись проверки снимается владельцем области с причиной; сохранившаяся правка отказывает | `plugins/taskboard/test/verification-contract.test.mjs` |
| Запись доски атомарна: строка и сведения проверки вместе | [taskboard-write-integrity](analysis/taskboard-write-integrity.json) |
| Проекции `state/views/` собираются из журнала и записей анализа, руками не правятся | `plugins/project-state/test/views.test.mjs` |
| Документ не повторяет состояние: версия, номер задачи, счётчик | `node scripts/check-documentation.mjs` |
| В журнал не попадают тела запросов, ключи, заголовки | `make test` |
| Замер запроса — после сериализации, с одним изменённым фактором | [request-cache](analysis/request-cache.json) |
| Рисунок карты не является состоянием проекта | [designmap-pages](analysis/designmap-pages.json) |
| Пресет знает приёмку заранее | персоны, `CHILD_POLICY` |

## 5. Путь запроса

1. Входящие сообщения, инструменты шага, разделы системного промпта (персона, инструкции проекта, правила роли).
2. `agent/pre-step`: маршрут и контекст шага; выбранные инструменты задним числом не меняются.
3. Видимые разделы и сообщения истории; запрос собирает адаптер, точка измерения — **после сериализации**, не в плагине.
4. Ответ модели, следующий шаг; после компакции состояние берётся из записи анализа и доски.

## 6. Изменение и инвалидация

Решение — архитектора, исполнение — оркестратора.

- **Новый компонент** — строка в §2 с путём и владельцем; его записи видны в инвентаре `node scripts/check-boundaries.mjs --list`.
- **Смена контракта** — правится строка контракта и держащий его инвариант; потребители там же.
- **Смена владельца данных** — одна запись-владелец в §2; второй писатель — находка `I-ONE-WRITER`.
- **Новая внешняя зависимость** — строка в §2 или §3; выход за шов — только исключением в `scripts/check-boundaries.mjs`.
- **Требование не вписывается** — архитектор меняет архитектуру решением (правка файла) либо говорит, что фича не вписывается, и в реализацию не идёт.

**Устаревание.** Инвентарь печатает `node scripts/check-boundaries.mjs`; расхождение этого файла с деревом отчёт не ловит — устаревание признают оркестратор и архитектор.

**Связь с картой дизайна.** `designmap/pages/system.excalidraw` и `designmap/pages/target-workflow.excalidraw` иллюстрируют компоненты §2; идентификаторы компонентов — в §2, страниц — в имени файла: карта иллюстрирует, файл решает.
