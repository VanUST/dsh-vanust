# Explain in HTML

Custom, disposable software can make an idea easier to understand.

1. Find the reader's main question. Choose one example that makes the mechanism concrete. Keep facts, assumptions, and unknowns distinct.
2. Create a complete HTML page. Prefer one self-contained file with embedded CSS and JavaScript unless the user already has an app or needs separate assets.
3. Add interaction where it teaches: change an input, reveal a step, compare scenarios, or watch a mechanism. Show what changed and why. Avoid decorative controls.
4. Use clear hierarchy, readable type, and short explanations. Give controls labels, keyboard access, and visible focus. Support narrow screens and reduced motion.
5. Open the page, exercise its controls, and check a narrow viewport. Verify the underlying example as well as the appearance. Fix issues and return the HTML with a short instruction for opening it. Disclose anything you could not test.

Use animations to direct attention. Keep the page as small as the explanation allows. Do not publish it unless the user asks. In this deployment, write the file into the workspace and use the `present` tool so the Sidebar preview can show it.
